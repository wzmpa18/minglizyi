## 二、各协议详细分析

### 1. MIT License

**适用项目**：iztro、suangua、ziwei、TCM-Learning-Assistant、tcm-cli（5个项目）

**协议要点**：
- 允许：商用、修改、分发、私有使用、再许可
- 要求：保留版权声明和许可声明
- 免责：软件按"原样"提供，无任何担保
- 专利：无明确专利授权条款

**风险分析**：
- **风险等级**：低
- MIT 是最宽松的开源协议之一，对商用几乎无限制
- 唯一义务是在分发时保留原始版权声明
- 适合商业集成和二次开发

**商用准入结论**：**完全允许**。可直接用于商业产品，无需开源衍生代码。建议在商业产品的"关于"或"鸣谢"页面保留原始版权声明。

---

### 2. AGPL-3.0 (GNU Affero General Public License v3)

**适用项目**：jishiyu（1个项目）

**协议要点**：
- 允许：修改、分发、私有使用
- 要求：分发时必须提供完整源代码（包括网络服务场景）
- 核心条款（第13条）：如果通过计算机网络远程交互使用修改后的程序，必须向所有用户提供获取对应源代码的途径
- 专利：包含专利授权条款
- 传染性：强 copyleft，衍生作品必须同样使用 AGPL-3.0

**风险分析**：
- **风险等级**：高
- AGPL-3.0 是"最强 copyleft"协议，网络服务（SaaS）场景下也必须开源
- 任何使用 jishiyu 代码的 Web 服务必须公开全部源代码
- 如果只是调用 API 而不修改代码，不受 AGPL 传染
- 商业集成风险：如果修改了 jishiyu 源码并通过网络提供服务，必须开源所有修改

**商用准入结论**：**受限**。
- 作为独立工具使用：允许（不修改源码，仅调用）
- 修改后通过网络提供服务：**必须开源**全部修改代码
- 嵌入商业产品（非网络服务）：修改代码必须开源，但可与其他私有代码共存
- 建议：如果商业产品需要深度集成 jishiyu，建议联系原作者获取商业授权或使用替代方案

### 3. ISC License

**适用项目**：mystilight-8char（1个项目）

**协议要点**：
- 允许：商用、修改、分发、私有使用
- 要求：保留版权声明和许可声明
- 免责：软件按"原样"提供，无担保
- 特点：ISC 是 MIT 的精简等价版本，功能上几乎完全相同

**风险分析**：
- **风险等级**：低
- ISC 与 MIT 在功能上等价，是最宽松的协议之一
- 对商用几乎无限制
- 唯一义务是保留版权声明

**商用准入结论**：**完全允许**。可直接用于商业产品，无需开源衍生代码。

### 4. MulanPSL-2.0（木兰宽松许可证 第2版）

**适用项目**：nihaixia（1个项目）

**协议要点**：
- 允许：复制、修改、分发、商用、专利授权
- 要求：保留版权声明、许可证声明、免责声明
- 专利：明确的专利授权条款（贡献者授予用户相关专利许可）
- 传染性：弱 copyleft，修改后可选择不同协议发布，但原有代码必须保留木兰协议
- 特点：中国主导的开源协议，中英文双语，符合中国法律体系

**风险分析**：
- **风险等级**：中
- MulanPSL-2.0 是 OSI 认证的宽松协议，整体风险较低
- 但 nihaixia 项目存在以下合规瑕疵：
  - 缺少独立的 LICENSE 文件（仅 README 中声明）
  - 基于 nihaisha-skill（上游项目）二次开发，需确认上游协议兼容性
  - 项目使用 CC 许可的数据内容（讲义蒸馏）与代码许可的关系不够清晰
- 商用风险：MulanPSL-2.0 本身允许商用，但需注意数据内容的版权归属

**商用准入结论**：**需审查后决定**。
- MulanPSL-2.0 协议本身允许商用
- 但需确认以下问题后再商用：
  1. 补充独立的 LICENSE 文件
  2. 确认上游项目（nihaisha-skill）的协议兼容性
  3. 确认倪海厦讲义蒸馏内容的版权归属和数据使用许可
  4. 确认项目中的医案数据是否涉及隐私权
- 建议：商用前完成上述合规审查，并在产品中明确标注数据来源

4. 建议在所有项目中添加 `SPDX-License-Identifier` 标准头注释
