## 2. 内容合规红线

### 2.1 合规红线总则

基于《网络安全法》《互联网信息服务管理办法》《移动互联网应用程序信息服务管理规定》等法规，本项目涉及的**命理类**和**中医类**内容，必须遵守以下红线：

| 内容类别 | 合规红线 | 强制标注规范 |
|----------|---------|-------------|
| **命理类** | 禁止声称具有预测功能、禁止承诺结果准确性、禁止引导重大人生决策 | 「传统文化娱乐参考，不构成人生决策建议」 |
| **中医类** | 禁止疾病诊断、禁止处方开具、禁止疗效承诺、禁止替代医疗建议 | 「传统文化科普记载，不构成医疗建议」 |

### 2.4 30个违规点逐项改造方案

基于前期合规审查，本项目所依赖的3个中医类开源项目（nihaixia、tcm-cli、TCM-Learning-Assistant）共发现**30个违规点**。以下逐项说明改造方案：

---

#### 2.4.1 TCM-Learning-Assistant（8个违规点）

##### 违规1：【严重】AI辅助辨证推荐方剂功能

| 项目 | 内容 |
|------|------|
| **源文件** | `src/main.py`（第9行、第63行、第102-104行） |
| **违规内容** | 项目描述中声明"AI辅助辨证分析 -- 根据症状推荐方剂"功能；预留了 `/diagnosis/recommend` 端点 |
| **违规类型** | 疾病诊断 + 处方开具 |
| **改造方案** | 删除 `diagnosis` 诊断推荐模块及其路由注册；将 `main.py` 中相关描述改为：「传统文化科普记载，不构成医疗建议」 |

##### 违规2：【严重】前端"智能辨证"功能入口

| 项目 | 内容 |
|------|------|
| **源文件** | `frontend/index.html`（第22行、第70-73行） |
| **违规内容** | 导航栏包含"智能辨证"按钮，首页展示"AI辅助辨证分析"功能卡片 |
| **违规类型** | 疾病诊断 |
| **改造方案** | 删除"智能辨证"导航按钮和功能卡片；替换为"方剂学习"、"药材知识"等传统知识科普入口 |

##### 违规3：【严重】数据文件中"主治"字段映射具体疾病

| 项目 | 内容 |
|------|------|
| **源文件** | `data/formulas.json`、`data/herbs.json` |
| **违规内容** | `indications`（主治）字段将方剂/药材与具体疾病直接关联，隐含"此方/此药可治此病"的医疗建议 |
| **违规类型** | 替代医疗建议 |
| **改造方案** | 将 `indications` 字段重命名为 `traditional_usage`；在字段描述前添加：「以下为传统文化典籍记载，不构成医疗建议」；将 `efficacy` 字段重命名为 `traditional_function` |

##### 违规4：【严重】"现代应用"和"临床案例"字段

| 项目 | 内容 |
|------|------|
| **源文件** | `data/formulas.json`（每条方剂包含 `modern_research` 和 `clinical_cases` 字段） |
| **违规内容** | `modern_research` 包含疗效承诺内容；`clinical_cases` 包含替代医疗建议 |
| **违规类型** | 疗效承诺 + 替代医疗建议 |
| **改造方案** | 删除 `modern_research` 字段中的"功效"描述，仅保留"成分分析"等客观研究信息；将 `clinical_cases` 字段中的"现代应用"改为"典籍记载应用"并加免责声明 |

##### 违规5：【中等】数据模型中"clinical_cases"字段设计

| 项目 | 内容 |
|------|------|
| **源文件** | `src/models/formula.py`（第192-195行） |

##### 违规6：【中等】API接口描述中的"方剂推荐"语义

| 项目 | 内容 |
|------|------|
