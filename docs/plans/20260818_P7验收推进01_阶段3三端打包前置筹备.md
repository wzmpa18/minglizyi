## 一、统一架构原则（红线）

- **原生容器 + H5 业务页 Hybrid 架构**：业务功能 100% 复用现有 H5 页面与后端接口（`/api/auth/*`、`/api/academy/*`、统一支付、推广归因），不重写核心功能、不新建独立的订单/会员/支付/推广/题库系统
- 现有 H5 站点 `https://yandaoguoxue.yandao.vip`（Next.js 静态导出 + PM2 后端）即业务载体，三端容器仅做原生壳与原生能力桥接
- 现有代码已预留 Capacitor 探测点（`shareService.ts` 的 `window.capacitor.Plugins.Share` 分支），容器化路径天然兼容

## 二、iOS 端核心适配清单（优先启动）

### 2.1 StoreKit IAP 内购

| 商品 | 类型 | 说明 |
|------|------|------|
| 会员订阅 | 消耗型/订阅型 | 对应现有会员体系档位（后台 toolConfigStore 可视化配置） |
| AI 单次解读 | 消耗型 | 对应现有 Paywall 按次付费商品 |

必须实现：购买流程、恢复购买、App Store 收据校验（服务端二次校验，复用现有订单表幂等）、退款同步（App Store Server Notifications V2 → 服务端权益回收）、沙盒/生产环境隔离。

**合规红线**：数字商品一律走 IAP，不得引导外部支付（App Store 审核条款 3.1.1）。

### 2.2 Universal Link

- `apple-app-site-association` 托管于 `https://yandaoguoxue.yandao.vip/.well-known/`（Nginx 静态文件，application/json）
- 邀请二维码/分享链接携带的 `ref/ts/sig` 参数经 Universal Link 唤起 App 后透传给 H5 容器（`InviteCaptureInit` 全站捕获逻辑无需改动，天然兼容）
- Associated Domains 能力申请与 entitlements 配置

### 2.3 原生基础能力

启动页、底部导航（Tab 容器承载 H5 首页/发现/好友/学习/我的五 Tab，与现有 H5 底部导航对齐）、WebView 加载异常兜底页（断网/超时重试）、登录态安全存储（Keychain 存 access token，替代 localStorage）、系统分享（已预留 Capacitor Share 分支）、APNs 推送权限适配。

## 三、安卓端核心适配清单

- 官方渠道数字支付：Google Play Billing（与 iOS IAP 同构：购买/恢复/服务端校验/退款同步），对齐 App Store 合规口径
- App Link：`assetlinks.json` 托管于同一 `.well-known/`，与 iOS Universal Link 共用归因参数协议
- 原生基础能力与 iOS 对齐：启动页、底部 Tab、异常兜底、登录态加密存储（EncryptedSharedPreferences/Keystore）、系统分享、FCM/厂商推送
- 应用包名/签名证书规划（release keystore 托管，见第五节）

## 四、微信小程序端核心迁移清单

### 4.1 一期迁移范围（6 个模块）

首页工具入口、核心排盘工具、学习题库、推广中心、个人中心、会员与已购权益。

### 4.2 关键适配点

- **微信支付**：现有 H5 支付体系适配 JSAPI 下单（复用现有订单引擎，仅新增渠道参数）
- **小程序分享**：onShareAppMessage / 分享卡片，落地页路径映射到小程序页面路由
- **场景值邀请归因**：扫码进入场景值（1011/1047/1048 等）解析 → 还原 `ref/ts/sig` → 注册时经现有归因接口上送；注意小程序无 localStorage，归因上下文改存本地 Storage API（接口签名不变）
- **WebView 混合**：重交互页面（紫微叠宫等）可用 web-view 承载 H5，但需域名配置业务域名白名单
- **登录体系**：现有手机号+验证码登录流程在小程序内以表单页实现，后端接口零改动

## 六、账号与资质前置准备清单（项目方申请）

1. Apple Developer Program 账号（公司主体）+ App Store Connect 创建 App（Bundle ID 规划）
2. Google Play Console 账号 + 应用创建（包名规划，与 iOS Bundle ID 对齐）
3. 微信小程序账号（企业认证）+ 微信支付商户号关联
4. IAP 商品在 App Store Connect / Google Play Console 后台创建（与 toolConfigStore 会员档位对齐）
5. 服务器 `.well-known/` 目录准备（AASA + assetlinks.json）
6. 隐私政策/用户协议 App 版本补充（现有 H5 版本已有，需补充原生 SDK 数据收集说明：推送、统计）

## 八、风险提示

1. **审核风险**：占卜/命理类内容在 App Store 与 Google Play 均有被拒先例，上架材料需强调「文化学习/传统文化教育」定位（现有内容已书面化、去恐吓化，具备基础）；拒审预案：准备内容分级说明与申诉材料
2. **IAP 佣金**：苹果对数字商品抽成 15%~30%，会员/AI 解读定价需重核算（成本模型确认后再定价，避免上线后调价）
3. **小程序类目**：玄学类目在小程序平台同样受限，「文化/教育」类目申报材料需项目方确认
4. **归因兼容**：Universal Link/App Link 冷启动参数透传需真机专项测试（iOS 剪贴板权限弹窗会干扰裸链接方案，签名链接方案不受影响）
