## 二、分享归因全场景核查（代码 + 线上包双实证）

归因链路四级闭环：

1. **分享入口统一带参**（`src/components/ShareButton.tsx`）
   - 挂载时经 `getInviteLink()` 拉取签名参数（24h缓存）
   - 复制链接/生成海报/系统分享三条通道统一走 `buildAttributedLink()`：优先附加 `ref/ts/sig`（与服务端 `resolveInviteAttribution` 同口径），降级附加邀请码 `code`
   - 覆盖 30+ 工具结果页（八字/紫微/六爻/梅花/奇门/塔罗/占星/万年历等全部 ShareButton 调用方）
2. **学习成就页带参**（`src/app/profile/page.tsx` QRModal）
   - 主路径：签名邀请链接 + 本地二维码生成（无境外依赖）
3. **落地页全站捕获**（`src/components/InviteCaptureInit.tsx` 挂载于根 layout `src/app/layout.tsx:51`）
   - 邀请链接可指向站内任意页面，`ref/ts/sig/code` 统一捕获入 localStorage（TTL 30天）
4. **注册/登录上送归因**（`src/lib/loginService.ts` registerWithPhone、`src/lib/inviteApi.ts` loginWithCodeServer）
   - 验证码登录（含自动注册）同样携带归因上下文 + 设备指纹

线上实证：v25.0.31 现役 chunk `/_next/static/chunks/2-au5z891zgt1.js` 同时包含 `yandao_invite_ctx`（全站捕获）与 `yandao_invite_link_cache`（签名链接）关键代码，公网版本 `version.json` = `v25.0.31_D20260818`。

已知降级路径（不阻塞验收）：个人主页二维码弹窗在签名链接接口失败时降级为裸 `?ref=` 链接，后端按防伪造规则不采信（记 SIG_INVALID 审计），不会产生错误绑定，仅该次降级分享无法归因。

## 五、两台真机录屏验收清单（交付项目方）

> 设备：真机1（邀请人，已登录账号A）、真机2（新用户，建议恢复出厂或清除站点数据+更换网络IP）
> 全程录屏，单视频不间断为佳

### 第一段：正常全链路（必过）

1. 真机1 登录 → 我的 → 推广中心 → 生成邀请二维码
2. 依次验证三项能力：保存相册、系统分享、复制链接（复制后在真机2浏览器粘贴确认带 `ref/ts/sig` 参数）
3. 真机2 扫码/打开链接进入落地页 → 手机号+验证码完成注册
4. 真机1 推广中心查看：邀请数+1、注册积分50到账、被邀请人明细出现
5. 真机2 完成任意一笔有效付费（会员或AI单次解读）
6. 真机1 验证：首付费奖励200到账、明细新增记录
7. 前后台核对：推广中心页数据与后台 invite_audit/invite_rewards 完全一致

### 第二段：防作弊抽验（至少3项）

1. 真机1 用自己的邀请码给自己注册新号（同设备）→ 应被拦截不绑定，后台留痕 SELF_OR_LINKED_DEVICE
2. 同设备连续注册3个以上新账号再带邀请注册 → 拦截，留痕 DEVICE_BATCH_REGISTER
3. 同一IP 24小时内第5次以上带邀请注册 → 拦截，留痕 IP_BATCH_REGISTER
4. 手工篡改复制链接中的 sig 参数为任意值后注册 → 不绑定，留痕 SIG_INVALID

### 第三段：分享归因抽验

1. 真机1 在任一工具（如八字）结果页点分享 → 复制链接 → 确认含 `ref/ts/sig`
2. 真机2 打开该链接 → 注册 → 真机1 推广中心应出现新邀请且绑定成功
3. 真机1 个人主页二维码弹窗重复步骤2

### 判定标准

- 全流程无阻断、奖励金额与配置一致（注册50/首付费200，以服务器 .env 为准）
- 异常场景全部命中拦截规则且后台可查留痕
- 前后台数据零差异
- 录屏文件留存归档（建议命名：`P7阶段1_真机验收_YYYYMMDD.mp4`）
