| 项 | 实现 | 验证 |
|---|---|---|
| 二维码数据源 | `GET /api/auth/invite/link`（JWT 鉴权，服务端 HMAC-SHA256 签名） | 公网未带 token 探针 401（路由存在+鉴权生效） |
| 本地生成 | `qrcode` 包（新增依赖，`src/lib/qrLocal.ts` 统一助手），彻底移除境外 qrserver 依赖 | 服务器 `node -e require('qrcode')` OK；全站仅剩注释提及 |

| 链接复制 | clipboard + 降级 execCommand | 产物门禁 OK |

### 1.2 全注册入口统一归因
| 入口 | 归因逻辑 |
|---|---|
| 手机号注册 `/api/auth/register` | `InviteCaptureInit` 全局捕获 ?ref/&ts/&sig/?code → `loginService.registerWithPhone` 注入 inviteRef/inviteTs/inviteSig + deviceId 指纹 |
| 验证码登录 `/api/auth/login-code` | 新用户自动注册（同上归因）；老用户未绑定则补归因（首绑优先、永久生效） |
| 签名校验 | ts 防未来时间戳 + HMAC 签名，伪造 ref 一律不采信并记审计 |

### 1.3 单层积分奖励
- 邀请注册：`INVITE_REWARD_REGISTER=50`（env 已注入服务器 .env）
- 邀请首次有效付费：`INVITE_REWARD_FIRST_PAY=200`，`paymentRoutes.js` 订单支付成功钩子触发
- 只写 level=1 关系、只奖直接邀请人；`invite_rewards` 唯一约束保证幂等
- 奖励明细可查：`GET /api/auth/points/transactions`（公网 401 鉴权探针通过）+ `GET /api/auth/invite/overview`

### 1.4 防作弊五类场景（`resolveInviteAttribution`）
| 场景 | 拦截码 |
|---|---|
| 自邀/关联账号（邀请人与被邀人同设备） | SELF_OR_LINKED_DEVICE |
| 同设备批量注册（≥3 账号） | DEVICE_BATCH_REGISTER |
| 同 IP 批量注册（24h ≥5 次） | IP_BATCH_REGISTER |
| 多来源冲突 | 取最高可信源（signed_link > code），冲突记审计 |
| 被邀人已绑定 | ALREADY_BOUND_FIRST_WINS（首绑优先，不可覆盖） |

全部拦截结果写 `invite_audit` 审计表（invitee/inviter/source/result/reason/ip/device_id）。

### 1.5 分享入口统一携带邀请标识
- `ShareButton` 全站复用：优先取 `/invite/link` 签名参数（ref/ts/sig）附加到任意分享 URL；未登录降级邀请码 `?code=`
- 工具结果页、学习成就页、动态分享共用同一套签名链接构建逻辑
