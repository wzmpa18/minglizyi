## 一、本版整改内容（对应项目方两大反馈）

### 1. 好友点击进聊天页无输入框、无法发消息

**根因**：聊天输入栏与底部 Tab 栏同为 `fixed bottom-0`，Tab 栏 `zIndex:1000` 完全盖住输入栏（v25.0.36 已修复"点好友跳不进聊天"的路由问题，本轮是进入聊天页后的第二层遮盖问题）。

**修复**：
- `BottomNav.tsx`：`/friends/chat*` 路径直接 `return null`（私聊页与底部 Tab 栏互斥，聊天场景不需要 Tab 栏）
- `friends/chat/[id]/ClientPage.tsx`：正常模式与管理模式底部操作栏均提 `zIndex:1001` + `paddingBottom: calc(8~12px + env(safe-area-inset-bottom))`（含弹窗统一规范底部安全区）

### 2. 通过分享注册成功但未绑定邀请人（实例：用户 100038「自由世界」）

**根因（服务器 DB 实证）**：`registerWithEmail` 邮箱注册链路**完全丢失邀请上下文**——不上送 `ref/ts/sig/deviceId/referrer_id`，服务端归因为空。手机注册（100029）归因正常，邮箱注册（100038）`invited_by` 为空。

**修复（三段）**：
1. **前端 `loginService.ts`**：`registerWithEmail` 与 `registerWithPhone` 同口径——统一读取 `getInviteContext()`（签名链接 ref/ts/sig 优先，邀请码次之）+ `getDeviceId()` 设备指纹 + `referrer_id` 上送；注册成功后 `clearInviteContext()`
2. **后端 `register_routes.js`**：`/register` 解构 `referrer_id`；纯 referrer_id（无签名）不直接采信（防伪造），但写 `invite_audit` 审计留痕（`UNSIGNED_REF_MANUAL_RECONCILE`）供人工对账
3. **人工对账补绑 `scripts/reconcile_invite_100038.js`**：按服务端 `bindInviteAndReward` 同款逻辑补绑 100038→100000 + 补发 50 分注册奖励（幂等可重复执行；`better-sqlite3` 按后端运行目录绝对路径引用）

**补绑结果（服务器 DB 复核）**：

```
users:      100038 自由世界 invited_by=100000 ✅
relations:  100000→100029(L1)、100000→100038(L1) ✅
rewards:    两笔 register 50分 granted ✅（邀请人余额 100 分）
```

**注册入口归因链路复核（全闭环）**：
- 全站落地捕获：`InviteCaptureInit` 挂 `layout.tsx`，任意页面带 `?ref=&ts=&sig=` 均捕获持久化（30 天 TTL）
- 手机注册 `registerWithPhone` / 邮箱注册 `registerWithEmail` / 验证码登录自动注册 `loginWithCodeServer` 三路均带签名参数 ✅
- 注册页 `?ref=` 进入隐藏邀请码输入框（显示"邀请人已自动绑定"）✅

### 3. 紫微斗数八项布局整改（用户逐条指令）

| # | 指令 | 实现 |
|---|---|---|
| 1 | 星曜横排一行全部排完，星多时主星不变副星杂曜变小 | `flexWrap:"nowrap"` 单行；主星沿用 12–15px 分档不变；副星/杂曜按宫格实测可用宽（106.5px − 预留）自动缩小（4–9px）至一行排完，严禁换行 |
| 2 | 每颗星含杂曜都要庙旺，在竖排星名正下方 | 去掉 `star.isMajor` 限制；`getStarBrightness` 缺数据默认「平」，全部星曜显示庙旺 |
| 3 | 右下角天干重复，去重沉底 | 只渲染一套宫干支，`bottom:0px` 最右下角沉底；身宫「身」字并入干支列；大限干支重复项移除 |
| 4 | 十二长生在右下角干支上面纵向竖排 | 长生列纵排于干支正上方（`bottom=干支实测高度`，2字干支16px / 3字含身24px 动态让位） |
| 5 | 大限流年天喜天马等动态星要有，在长生上面从右往左排 | E 区恢复并移至长生上方，`row-reverse` 从右往左、自下而上生长；每列 10 颗续列最多 3 列；层序大限→流年→流月→流日→流时→童限/小限不变 |
| 6 | 来因宫右侧靠边中间纵向显示 | `right:0, top:38%, writing-mode:vertical-rl` 竖排；与 E 区同宫时 E 区及星曜区整体左移让位 |
| 7 | 底部需要有童限 | 宫名旁童限/小限标记（选定流年后虚岁<起运岁=童限于命宫，否则小限于对应宫，规则与 ZW-TIME 引擎一致） |
| 8 | 本命盘宫位内流年小限数字 | `palace.ages` 小限岁数 + `ageRange` 大限区间**常显**（不再因点击大限隐藏） |

**防遮挡实测**：宫格 440×146px（aspectRatio 0.75÷4 行），右列三段自下而上 = 干支（16–24px）→ 长生（16px）→ 动态栏（`bottom=干支高+16`），互不重叠；A 区星曜按 `12 + 动态列数×8 (+来因11)` px 右侧预留。
