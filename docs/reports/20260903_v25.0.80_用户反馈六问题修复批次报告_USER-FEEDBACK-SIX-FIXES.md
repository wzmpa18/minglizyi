## 一、问题1：Gmail 邮箱收不到验证码 ✅ 已在生产生效（无需部署）

### 根因确诊（DNS 层，非代码）

腾讯云 SES API（GetEmailIdentity）显示 yandao.vip 四项记录 Status:true（历史检测缓存），但权威 DNS 实测矛盾：

| 记录 | DNSPod 面板状态 | 权威 DNS 实测（修复前） | 结论 |
|------|----------------|----------------------|------|
| TXT @ SPF `v=spf1 include:qcloudmail.com ~all` | **DISABLE（暂停）** | 不存在（NXDOMAIN） | 根因 |
| MX @ `mxbiz1.qq.com`（优先级5） | **DISABLE（暂停）** | 不存在 | 连带 |
| TXT `qcloud._domainkey` DKIM | ENABLE | 存在 ✓ | 正常 |
| TXT `_dmarc` `v=DMARC1; p=none` | ENABLE | 存在 ✓ | 正常 |

**根因**：早期切 CDN 时 @ 主机 TXT/MX 与 CNAME/显性URL 冲突被一并暂停，后网站改回 A 记录直连（82.156.228.87），SPF/MX 忘记恢复。腾讯云 SES 的验证状态是域名注册初期检测的历史快照，不会自动复查。

**影响链**：SPF 缺失 → Gmail 对腾讯云 SES（香港）IP 的无 SPF 邮件信任度极低 → 拒收/垃圾箱。QQ/163 等国内邮箱宽松可收（与用户反馈吻合：仅谷歌收不到）。

### 修复动作（DNSPod API，DeleteRecord+CreateRecord 恢复）

- 删除 DISABLE 的 SPF（RecordId 2317816590）→ 重建 ENABLE：`@ TXT v=spf1 include:qcloudmail.com ~all`（TTL 600）
- 删除 DISABLE 的 MX（RecordId 2317816250）→ 重建 ENABLE：`@ MX mxbiz1.qq.com. 优先级5`（TTL 600）
- 一次性脚本（用后即删）：backend_deploy/dnspod_fix_spf.js（复用 TENCENT_SES 密钥的 DNSPod TC3 签名）

### 验证（权威 DNS 直查）

```
$ nslookup -type=TXT yandao.vip classical.dnspod.net
yandao.vip  text = "v=spf1 include:qcloudmail.com ~all"   ✓
$ nslookup -type=MX yandao.vip classical.dnspod.net
yandao.vip  mail exchanger = 5 mxbiz1.qq.com.               ✓
```

邮件认证链路现全通：SPF ✓ + DKIM ✓ + DMARC ✓ + MX ✓。**用户可直接用 Gmail 重新注册验证**（DNS 已生效，TTL 600 秒内全球同步）。
